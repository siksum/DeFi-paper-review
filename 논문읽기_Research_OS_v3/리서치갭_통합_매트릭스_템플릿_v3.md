# 리서치 갭 통합 매트릭스

> 목적: 개별 논문의 limitation을 나열하는 것이 아니라, 여러 논문을 동일한 축으로 비교하여  
> **실제로 남아 있는 연구 공백과 그 근본 원인**을 추적한다.
>
> 최종 갱신: 2026-08-12. 이 파일은 현재 프로젝트의 활성 통합 매트릭스다.
> Gap의 연구 상태는 `PROPOSED / ACCEPTED / REJECTED / SUPERSEDED / UNRESOLVED`, 논문별 증거 판정은 `지원 / 부분 지원 / 약화 / 반박 / 무관 / 미확인`을 사용한다.

# 5. Gap Ledger

각 gap은 독립된 항목으로 관리한다.

현재 상세 evidence는 Oracles `E-001~012`, DeFiRanger `E-001~018`, DeFort `E-001~035`, DeFiScope `E-001~018`, Sereum `SER-E01~14`를 사용한다. Oracles의 기능 부재가 논문 목적상 비대상인 GAP-002·003·006은 gap 지지 근거로 세지 않는다. DeFiRanger·DeFort·DeFiScope는 직접 PMA 탐지 방법이므로 관측·predicate·출력·평가의 부재와 실제 실패 사례를 제한된 근거로 사용할 수 있다. Sereum은 재진입 방어 논문이므로 PMA 기능 부재는 세지 않고, 실제 instruction-level data dependency·event-less observation·semantic-loss 오탐이라는 **인접 양성 근거**만 사용한다. 아직 어떤 gap도 확정하지 않는다.

# 22. Automation Update Rules

새 논문 `P_new`가 추가될 때:

1. 기존 Gap Ledger의 모든 `UNRESOLVED/PROPOSED` gap과 비교한다.
2. `P_new`가 문제를 해결하면 논문별 판정을 `약화` 또는 `반박`으로 기록하고, gap 상태 변경 후보를 남긴다.
3. 기존 논문과 충돌하는 claim을 Contradiction Matrix에 추가한다.
4. 새로운 구조적 limitation이 발견되면 gap candidate를 추가한다.
5. Methodology Decision에 영향을 주면 기존 결정을 자동 변경하지 않고 `UNRESOLVED` 재검토 후보로 표시한다.
6. `[ACCEPTED]` claim/method를 반박하는 새 근거가 나오면 변경 영향과 새 버전 후보를 올린다.
7. 모든 UNKNOWN은 별도 목록으로 유지한다.
