## 관련성 판정

- 읽기 전 triage:
  - Primary track: `Track A — Core Method / Detection`
  - Secondary track: `없음`(실제 사건 측정 결과는 방법 평가 근거로만 사용)
  - 근거: transaction trace를 CFT로 만들고 DeFi action으로 lifting한 뒤 8개 규칙으로 PMA를 탐지하는 직접 방법론이다.
  - 반드시 추출: 관측 입력, semantic lifting, detection predicate, 역할·손익 출력, 평가 모집단, 오류 원인, 적용 한계.
  - 굳이 채우지 않음: 논문이 제시하지 않은 반사실 손실식과 임의의 graph schema.
  - 예상 용도: 핵심 비교 baseline, protocol 지식 의존성과 hard-negative 실패의 직접 근거.
- 분류: `핵심 PMA / 의미 복원 / 사후·실시간 transaction 탐지`
- `[V]` 직접 비교 대상이다. 원시 EVM transaction trace를 DeFi action으로 lifting하고, 그 action pattern으로 PMA를 탐지한다. 근거: Abstract, Sections IV-V, pp. 1, 4-8.
- 우리 연구와 직접 연결되는 부분:
  - raw execution과 high-level DeFi semantics 사이의 gap
  - transaction 내부 cash/token flow 구조
  - basic action에서 advanced action으로의 semantic lifting
  - 고수준 action pattern 기반 PMA 판정
  - atomic transaction 범위와 protocol-specific external information의 한계
- 논문의 목적과 다른 부분:
  - 범용 causal witness 구성
  - 반사실 manipulation-attributable gain 계산
  - 명시적인 loss bearer 귀속
  - multi-transaction/multi-block 분석

# 2. 논문이 푸는 문제

## 저자의 문제 정의

- `[V]` 기존 smart-contract vulnerability detector는 reentrancy·integer overflow 같은 코드 취약점에 집중하며, 여러 contract에 걸친 DeFi 논리 행위를 이해하지 못해 PMA를 직접 탐지하기 어렵다. 근거: Section I, pp. 1-2.
- `[V]` 원시 transaction에서 관측되는 invocation·event·token transfer와 `trade`, `deposit`, `borrow` 같은 고수준 금융 의미 사이에 semantic gap이 있다. 근거: Sections I, IV, pp. 1, 4.
- `[V]` 논문은 두 종류의 PMA를 대상으로 한다.
  - Type I: 취약한 DeFi contract에 원치 않는 trade를 수행시키고 공격자가 역방향 거래로 이익을 얻는 유형
  - Type II: DEX의 quotation·reserve·외부 token total supply 등에 의존하는 평가값을 조작해 과도한 borrow·withdraw를 수행하는 유형
  - 근거: Section III-B/C, pp. 3-4.

## 우리의 문제와의 관계

- 직접 해결하는 부분:
  - transaction trace와 event를 action-level representation으로 lifting
  - token flow 연결을 이용한 hoard cost와 dump revenue 경로 추적
  - 일부 state-read 존재를 이용한 조작 pool과 borrow/withdraw 사이의 dependency 후보 연결
- 전제로 주어지는 부분:
  - 3 basic actions와 5 advanced actions의 ontology
  - 8개 attack pattern
  - internal ledger를 해석하기 위한 protocol별 external information
- 다루지 않는 부분:
  - general distortion/reference 정의
  - 특정 read 값이 실제 계산 결과에 영향을 미쳤다는 세밀한 data dependency
  - attacker address cluster와 최종 beneficiary attribution
  - direct consumer와 최종 loss bearer의 분리
  - counterfactual attack gain과 victim loss
- 이 논문만으로 말할 수 없는 것:
  - 모든 형태의 PMA에 일반화됨
  - 임의 EVM protocol에서 adapter 없이 동일한 recall을 얻음
  - PMA 전체 모집단에 대한 recall
  - 정상 arbitrage·liquidation과 원리적으로 완전히 구별함

## 범위 반례

- `[V]` transfer-fee token, 정상 DEX fee transfer, 자동 buyback은 pattern과 일치해 false positive가 발생했다. Section VII-B, p. 9.
- `[V]` 여러 transaction에 걸친 공격은 구조적으로 탐지할 수 없다. Discussion, p. 12.
- `[V]` ERC-20 Transfer event가 없거나 비표준 advanced action 구조를 가진 protocol은 semantic action을 놓칠 수 있다. Sections VII-A, IX, pp. 9, 12.
- `[I]` 이익이 있는 정상 arbitrage나 liquidation 자체를 별도 hard-negative predicate로 구분하는 것이 아니라, 8개 attack pattern으로 후보를 좁힌다.

## 입력과 정답의 분리

- 방법 입력:
  - invocation trace, events, native/ERC-20 flows
  - internal ledger용 수동 external information
  - predefined semantic combination rules와 8개 attack patterns
  - offline/online price information
- 평가에 사용:
  - 수동 annotation한 advanced-action ground truth
  - 26개 알려진 incident와 탐지 결과에 대한 수동 TP/FP 판정
- `[V]` 알려진 attacker/victim address label을 탐지 입력으로 사용한다고 보고하지 않는다.
- `[V]` 다만 attack pattern 자체가 기존 공격 이해에서 만들어졌으므로 attack-family prior knowledge에는 의존한다. Discussion, p. 12.
- preferred source → fallback → 실패 영향:
  - standard Transfer event → 수동 external information → 둘 다 없으면 basic/advanced action 누락
  - token flow로 같은 단위 비교 → offline/online price oracle 보조 → 둘 다 불가능하면 profitability 비교 불완전

## 논문이 실제로 연결하는 가장 긴 경로

`주소가 수행한 advanced action → token hoard → pool 관련 trade/transfer/mint/burn → state-read가 포함된 borrow/withdraw 또는 같은 pool의 dump → cost보다 큰 revenue → 8개 pattern 중 하나`

이 경로는 우리 목표의 다음 부분을 부분적으로 덮는다.

`행위자 후보 → 개입 action → pool 관련 상태 변화 → state-read 존재 → 정산 action → 수익 관계`

하지만 다음 연결은 비어 있다.

- 실제로 왜곡된 경제값의 식별과 정상 reference
- read 반환값에서 정산 결과까지의 data dependency
- 주소 통제 주체와 최종 beneficiary
- consumer와 최종 loss bearer 사이의 손실 전가
- 관측 결과와 counterfactual 결과의 차이

- `[V]` profitability는 최종 보고값만이 아니라 attack pattern 적용 전 hoard-and-dump 후보 필터다. Section V-C, p. 7.

## DQ-08에 주는 증거

DeFiRanger 한 편만으로 protocol-specific 지식 정책을 확정할 수는 없다. 다만 다음 후보 설계를 강하게 지지한다.

1. protocol-independent core와 optional enrichment를 분리한다.
2. adapter 없음/있음 두 조건의 복원률과 `UNKNOWN` 비율을 따로 평가한다.
3. adapter가 없을 때 누락을 잘못된 의미로 강제하지 않는다.
4. protocol-specific knowledge의 수량, 작성 비용, 적용 범위를 artifact에 공개한다.

근거는 external information 부족이 semantic FN의 대부분을 차지한다는 점이다. 따라서 “adapter를 전혀 쓰지 않는다”와 “adapter 의존성을 숨긴다” 사이에서 선택할 문제가 아니라, core가 무엇을 증명하고 enrichment가 무엇을 추가하는지 분리하는 문제가 된다.

## 가져올 수 있는 것

- Invocation·Event·Basic·Advanced action을 단계적으로 분리하는 구조
- action node마다 원시 evidence를 연결하는 방식
- inter-contract token transfer를 무조건 merge하지 않고 connection으로 보존하는 아이디어
- semantic recovery 자체를 별도 ground truth로 평가하는 partial-task evaluation
- 실제 false positive와 false negative 원인을 semantic failure와 detection failure로 분해하는 방식

## 그대로 가져오면 안 되는 것

- 5개 advanced action을 완전한 ontology로 간주
- state-call 존재를 곧바로 값 consumption의 증명으로 간주
- hoard-and-dump profitability를 실제 P&L 또는 attack-attributable gain으로 간주
- pattern의 trader/debtor를 곧바로 attacker identity로 간주
- 취약 contract를 곧바로 최종 loss bearer로 간주
- 선택된 incident set 탐지를 전체 PMA recall로 해석

## 한 문장 결론

> DeFiRanger는 invocation·event 기반 CFT와 semantic lifting으로 atomic EVM transaction의 DeFi action 및 일부 pool-to-settlement dependency를 복원하지만, protocol-specific external information과 predefined patterns에 크게 의존하고 value-level consumption, control-based attribution, counterfactual gain/loss를 구성하지 않으므로 우리의 causal-evidence gap을 **부분 지원**한다.
