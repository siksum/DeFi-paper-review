## 이 논문을 읽는 이유

- 가격 조작 공격을 탐지하지는 않지만, 공격자가 목표 가격을 만들기 위해 필요한 자본과 공격의 수익 가능성을 계산한다.
- 풀의 유동성, AMM 곡선, TWAP 구간과 대출 프로토콜의 담보인정비율(LTV)이 공격 난이도에 미치는 영향을 보여준다.
- 현재 PMA 연구에서 `최소 어느 정도의 자금이 필요했는가`, `실제로 얼마를 투입했는가`, `모든 비용을 제하고 얼마를 벌었는가`를 분석할 근거 후보가 된다.

# 1. 5줄 핵심 요약

1. 대출 프로토콜이 DEX 가격을 담보평가에 사용하면, 공격자는 DEX 가격을 부풀려 정상보다 많은 자산을 빌릴 수 있다.
2. 그러나 가격을 움직이는 데도 자본과 손실이 필요하므로, 공격으로 얻는 가치가 조작비용보다 커야 경제적으로 이익이 된다.
3. 논문은 AMM과 TWAP 수식으로 목표 가격을 만들기 위한 거래량을 계산하고, LTV로부터 필요한 가격 상승폭을 계산한다.
4. 특정 시뮬레이션에서 Constant Product에는 총 필요자원이 최소가 되는 가격·담보 조합이 있었고, StableSwap은 더 적은 자원으로 조작될 수 있었다.
5. 현재 연구에는 `조건부 최소 순간 자금 → 실제 동원·투입 자금 → 회수 불가능한 비용 → 실제 순이익`을 구분하는 평가 관점을 차용할 수 있다.

## 공격 구조

```text
DEX에서 대량 거래
  → 풀의 토큰 비율과 가격 변화
  → 현재가격 또는 TWAP 왜곡
  → 대출 프로토콜이 왜곡된 가격으로 담보평가
  → 정상 상태보다 많은 자산 차입
  → 조달자금 상환 후 경제적 결과 발생
```

## Concept C2 — 필요자본·공격비용·순이익의 구분

### 쉬운 설명

[ANALYSIS]

```text
플래시론 원금 = 공격 중 잠시 사용할 수 있었던 자금
```

# 6. 수식 / 모델 / 알고리즘

## Model M1 — Constant Product 목표가격의 필요 투입량

### 원 수식

\[
xy=k, \qquad \Delta x=\sqrt{p_jxy}-x
\]

### 변수

| Symbol | Meaning | Unit / Domain |
|---|---|---|
| `x`, `y` | 공격 전 두 토큰 준비금 | 각각의 토큰 수량 |
| `p_j` | 목표 조작가격 | quote/base 비율 |
| `Delta x` | 목표가격을 만들기 위해 넣을 token x | token x 수량 |

### 이 수식이 설명하는 것

현재 풀 상태에서 특정 가격을 만들기 위해 한쪽 토큰을 얼마나 투입해야 하는지 설명한다.

### 가정

## Model M2 — Lending 가격 손익분기 조건

### 원 수식

\[
Profit=(C\times LTV+C\times LTV\times\epsilon)-C
\]

\[
\epsilon\ge\frac{1}{LTV}-1
\]

### 변수

| Symbol | Meaning | Unit / Domain |
|---|---|---|
| `C` | 공격자가 제공하는 담보가치 | 논문은 pool liquidity 대비 정규화 |
| `LTV` | 담보가치 중 차입 가능한 비율 | `0 < LTV < 1` |
| `epsilon` | 정상가격 대비 가격 상승률 | ratio |

### 이 수식이 설명하는 것

담보를 포기할 때 최소 어느 정도 가격을 올려야 담보의 실제 가치만큼 빌릴 수 있는지를 설명한다.

### 가정

최대 차입액을 모두 빌릴 수 있고 담보는 포기하며, 수수료·차입한도·가용 유동성을 생략한다.

### 입력값을 실제로 얻을 수 있는가?

LTV와 실제 담보·차입 flow는 관측 가능하지만 실제 protocol의 더 복잡한 risk logic을 반영해야 한다.

# 12. 반론 / 반례로 쓸 수 있는 내용

### 내 현재 가정이나 방법론을 반박할 가능성이 있는가?

- `가격을 더 크게 움직일수록 항상 더 많은 총자본이 필요하다`: 담보·조작비용 trade-off 때문에 총자원에는 최소점이 있을 수 있다.
- `평소 가격이 안정적인 시장은 조작에도 강하다`: StableSwap 예제가 반례가 된다.
- `플래시론 금액이 공격비용이다`: 조달 원금과 회수 불가능한 비용을 혼동한다.
- `수익성이 있으면 공격이다`: 정상 차익거래·청산도 이익을 낸다.
- `한 가지 최소자본 식을 모든 PMA에 적용할 수 있다`: 평가함수와 초기상태에 따라 비용곡선이 달라진다.

### 관련 Claim/Decision

D-001, D-004, D-007, D-010 및 정상 reference·actual P&L·manipulation-attributable gain 관련 열린 문제.

### 영향

`MINOR` — 기존 `ACCEPTED` 결정을 변경하지 않고 경제적 평가 후보를 구체화한다.

# 13. 이 논문에서 가져오면 안 되는 것

- 논문의 `attack cost`를 실제 플래시론 원금, 공격자의 최소 보유자본 또는 실제 손실과 동일시하지 않는다.

- Figure 3의 `pool liquidity 약 9.3배`를 일반적인 PMA 임계값으로 사용하지 않는다.
- 단순 lending profit 식을 실제 공격자 P&L이나 victim loss 식으로 사용하지 않는다.
- `수익 > 0`만으로 PMA를 판정하지 않는다.
- StableSwap 결과를 모든 Curve pool·vault·lending에 일반화하지 않는다.
- Theoretical feasibility를 실제 트랜잭션 탐지·인과 복원 능력으로 해석하지 않는다.
- Appendix의 `AC`를 실제 사건 비용으로 옮길 때는 `Δx`와 `Δy`의 가격 단위·valuation reference를 다시 확인한다. Algorithm 1의 `AC = Δx - Δy` 표기와 Equation A6의 `p_j` 환산은 같은 식으로 단순 해석하면 안 된다.
- TWAP 논의를 현재 atomic v1의 multi-block 지원 주장으로 확장하지 않는다.

# 16. 최종 Takeaways

### 반드시 기억할 개념 3개

1. 공격에 필요한 자본과 공격 후 되찾지 못한 비용은 다르며, 플래시론 원금은 그 자체로 공격비용이 아니다.
2. 공격 난이도는 왜곡률뿐 아니라 유동성, 초기상태, 평가함수, TWAP과 피해 프로토콜의 위험 설정이 함께 결정한다.
3. 수익성은 이미 복원한 공격의 경제적 결과를 뒷받침하는 증거이지 PMA의 독립적인 판정 기준이 아니다.

### 실제로 인용할 가능성이 높은 내용 3개

1. DEX oracle의 안전성은 protocol parameter, oracle window, manipulation duration, AMM curve와 liquidity를 함께 고려해야 한다(Algorithm 1).
2. 단순 lending model에서 LTV는 필요한 최소 가격 왜곡과 직접 연결된다(Equation 16-18).
3. 같은 조건에서도 AMM 곡선과 초기 reserve imbalance에 따라 조작자원이 달라질 수 있다(Figure 2-5).

### 내 방법론에 적용할 후보

1. 조건부 최소 순간 자금과 실제 동원·투입 자금 비교
2. 플래시론 원금, 회수 불가능한 비용, 실제 순이익과 조작 귀속 추가이익의 분리
3. 피해 프로토콜 설정을 포함한 사건 결과표와 평가함수별 민감도 분석

### 주의해야 할 가정

1. 논문의 attack cost와 profit은 단순 이론값이며 실제 P&L·victim loss와 같지 않다.
2. Constant Product의 약 9.3L와 StableSwap 결과는 특정 설정의 시뮬레이션이며 일반 threshold가 아니다.
3. TWAP과 multi-block 결과는 현재 atomic v1의 지원 범위로 자동 이전할 수 없다.

### 이 논문 때문에 새로 생긴 질문

1. `최소` 자본을 계산할 때 공격경로를 어디까지 고정해야 하는가?
2. 여러 토큰과 중간 자금 재사용을 공통 가치로 중복 없이 계산하려면 어떤 balance·valuation model이 필요한가?
3. 실제 순이익, manipulation-attributable gain과 victim counterfactual loss를 어떤 reference와 재실행으로 검증할 것인가?
