## 관련성 판정

- 분류: `핵심 PMA / 온체인 이상 탐지 / 주소·자금 흐름·함수 분석`
- `[V]` 직접 비교 대상이다. 대상 DeFi 앱의 현재 가격을 자체 역사 가격 범위와 비교하고, 관련 주소의 이익을 결합해 PMA alert를 생성한다. 근거: Sections 3.1-3.4, pp. 3-6.
- 우리 연구와 직접 연결되는 부분:
  - 공격 family별 pattern 대신 `가격 이상 + 이익`이라는 공통 행동 추상화
  - protocol별 가격 계산 전략과 protocol-independent 상태모델의 결합
  - historical price를 이용한 abnormal bound 계산
  - call trace, token transfer, swap을 이용한 관련 거래·함수·주소 분석
  - 가격 변동을 만든 주소와 이익을 얻은 주소가 다를 수 있다는 multi-account 가정
- 논문의 목적과 다른 부분:
  - value-level causal witness 구성
  - 동일 통제자 address clustering
  - 왜곡값에서 소비·정산까지의 정확한 data dependency
  - manipulation-attributable gain과 victim counterfactual loss

# 2. 논문이 푸는 문제

## 저자의 문제 정의

- `[V]` 코드 기반 취약점 탐지는 특정 DeFi business logic, third-party component, 실제 dynamic execution을 충분히 반영하지 못해 현실의 PMA를 직접 탐지하기 어렵다고 주장한다. 근거: Section 1, pp. 1-2.
- `[V]` 기존 behavior 기반 탐지는 제한된 pattern에 의존하므로 여러 주소와 복잡한 operation이 결합된 PMA에 취약하다고 주장한다. 근거: Section 1, p. 2.
- `[V]` 기존 도구는 공격 여부뿐 아니라 공격 과정과 관련 함수·주소·자금 흐름을 자동 분석하는 능력이 부족하다고 주장한다. 근거: Section 1, p. 2.
- `[V]` DeFort는 공격마다 별도 pattern을 정의하기보다 PMA의 공통 특성을 `abnormal price fluctuation`과 `profit`으로 추상화한다. 근거: Section 3.1, p. 3.

## 우리의 문제와의 관계

- 직접 해결하는 부분:
  - target pool·pair와 token의 current exchange rate 계산
  - 자체 과거 가격 대비 anomaly candidate 생성
  - 가격 이상 관련 transaction과 address candidate 수집
  - Transfer·Swap 기반 fund flow와 call sequence 추출
- 전제로 주어지는 부분:
  - target app과 관련 token·pool metadata
  - 주류 protocol 가격 계산 template
  - possible price function signature library
  - custom price calculation strategy와 prior-knowledge database
- 다루지 않는 부분:
  - 정확한 intervention state와 왜곡값 생성 연산
  - price return value가 settlement calculation에 미친 value-level dependency
  - 여러 주소의 동일 통제자 여부
  - canonical ledger 기반 full NAV와 debt·claim 평가
  - counterfactual attack gain과 final loss bearer의 손실
- 이 논문만으로 말할 수 없는 것:
  - 모든 PMA에서 `abnormal price + profit`이 충분조건임
  - arbitrary protocol을 manual adapter 없이 지원함
  - 공격자·피해자·수익자가 정확히 식별됨
  - 54건의 loss 금액을 DeFort가 직접 재계산해 맞힘
  - 실환경 전체 PMA recall과 false-positive rate

## 범위 반례

- `[I]` 정상적인 대형 swap이나 시장 급변으로 pool 가격이 역사 범위를 벗어나고 arbitrageur가 이익을 얻으면 핵심 predicate와 일치할 수 있다.
- `[I]` 조작된 가격을 직접 소비하지 않은 정상 arbitrageur도 Abnormal 이후 profitable address로 포함될 수 있다.
- `[I]` pool 가격은 정상 범위 안이지만 vault share price, oracle return, internal accounting value만 왜곡된 공격은 PCM adapter가 해당 값을 찾지 못하면 놓칠 수 있다.
- `[V]` BeltFinance의 복잡한 MultiStrategyToken 가격을 transaction execution trace에서 해석하지 못해 false negative가 발생했다. Section 4.3, p. 7.
- `[V]` Discover의 `getprice()` return value가 trace에 없어 false negative가 발생했다. Section 4.3, p. 7.
- `[I]` MagnateFi rug pull을 PMA에 포함하므로 연구 범위가 oracle·AMM manipulation보다 넓고, 단순 price setting과 자금 탈취의 경계가 불명확하다. Section 4.5, Table 2.

## 입력과 정답의 분리

- 탐지·분석 입력:
  - target DeFi app과 수동 metadata
  - 관련 token·pool·pair
  - RPC transaction과 block state
  - protocol price templates, signature library, custom price strategy
  - historical pool prices
  - Transfer·Swap과 function call sequence
  - multi-token 환산용 third-party token price
- 평가에 사용:
  - DeFiTainter와 DeFiHackLabs에서 수집하고 수동 검토한 54개 PMA incident
  - security-company reports와 수동 비교한 behavior description
  - 공개 사고 보고가 없던 기간을 normal로 가정한 D2
- `[V]` 알려진 attacker address를 탐지 seed로 사용한다고 보고하지 않는다.
- `[U]` 사건별 custom price strategy와 app metadata를 얼마나 수동 입력했는지 보고하지 않아 D1 결과의 자동화 정도를 판단할 수 없다.
- preferred source → fallback → 실패 영향:
  - mainstream protocol template → possible-price-function signature library → auditor custom strategy → 모두 실패하면 current price 계산 불가
  - execution trace return/call 정보 → source·bytecode 기반 수동 이해 제안 → 둘 다 없으면 Discover처럼 FN 가능
  - token별 동일 단위 flow → CoinGecko·CoinMarketCap 환산 → 가격을 얻지 못하면 multi-token profit 불완전

## Atomic transaction 내 transient state 관측 판정

- `[V]` DeFort는 직전·직후 블록 가격 하나만 비교하지 않고 `Th`의 여러 historical price로 HCM을 계산한다. Equation 5, p. 5.
- `[V]` 공격 분석과 Price Read에 transaction execution trace를 사용한다. Sections 3.1.3, 3.5.3, 4.3-4.4, pp. 4, 6-7.
- `[V]` Discover는 `getprice()` call detail·return value가 trace에 없어 FN이 발생했다. Section 4.3, p. 7.
- `[NR]` PCM을 internal call별 어느 execution point에서 계산하는지, per-call storage snapshot을 replay하는지, transient reserve·oracle value를 어떻게 보존하는지는 미보고다.
- `[NR]` 읽힌 가격 반환값에서 borrow·withdraw·mint·redeem 수량으로 이어지는 value-level dataflow는 제시하지 않는다.
- `[I]` 따라서 `tx 내부를 trace로 본다`는 것은 확인되지만, `atomic tx 종료 전에 가격이 원복되더라도 중간 왜곡값의 생성→소비→정산을 일반적으로 복원한다`는 강한 주장은 입증되지 않는다.
- `[I]` 후처리 state만 보면 `100→101`이지만 victim은 중간의 `500`을 소비한 사례에서는 exact execution-point value 관측이 필수이며, 현 명세로는 이 coverage를 재현할 수 없다.

## 인과 연결의 강도

논문이 실제로 연결하는 가장 긴 경로는 다음과 같다.

`target pool의 PCM 계산 → 자체 history 범위 이탈 → 관련 transaction·address 수집 → optional Price Read → Transfer·Swap fund flow → 관련 주소 subset의 양의 profit → PMA alert → associated function과 behavior description`

이 경로는 우리 목표의 다음 부분을 부분적으로 덮는다.

`행위자 후보 → 가격 관련 개입 후보 → pool 교환비 변화 → price-read 후보 → 자금 정산 후보 → 수익 주소 후보`

하지만 다음 연결은 비어 있다.

- exact state write에서 distorted value까지의 생성 연산
- independent reference와 counterfactual 정상값
- 특정 return value에서 지급·차입·mint·redeem 수량까지의 dataflow
- manipulation address와 profit address의 동일 통제 근거
- direct consumer에서 최종 loss bearer까지의 손실 전가
- actual wealth change와 manipulation-attributable gain의 차이

`Price Read`는 transient state이며 Abnormal에서 PDM이 참이면 직접 Profit으로 이동할 수 있으므로, 논문의 최종 alert predicate는 consumption edge를 필수로 요구하지 않는다. 따라서 완전한 causal witness보다 `anomaly + temporally related profit`에 가깝다.

# 8. 최종 판정과 정상 반례

## 판정 규칙

1. `[V]` target app의 관련 pool·pair마다 PCM으로 current exchange rate를 계산한다.
2. `[V]` HCM과 B를 이용해 모든 가격이 정상 범위면 Normal, 하나라도 범위를 벗어나면 Abnormal로 전환한다.
3. `[V]` abnormal price read가 관측되면 관련 address를 추가하고 다시 Abnormal로 돌아간다.
4. `[V]` 관련 주소 subset의 환산 profit 합이 양수이면 Profit으로 이동하고 PMA alert를 낸다.
5. `[V]` 탐지 뒤 address, fund flow, function call sequence를 분석한다.

### 필수조건과 미명세

- 필수조건: 관련 pool·pair의 price anomaly, 관련 address subset의 positive profit
- 비필수조건: Price Read state
- threshold: α, β와 minimal profit threshold가 존재하지만 실제 값·선정 근거 미보고
- runtime attack label: 불필요하다고 주장하지만 protocol/app metadata와 가격 knowledge 필요
- attack family pattern: 특정 family pattern은 사용하지 않으나 `abnormal price + profit`이라는 공통 behavior prior를 사용

- `[NR]` D1에서 attack 이전 history를 얼마나 사용했는지, α·β와 app-specific strategy를 어떻게 정했는지, full stream에서 공격 시점을 blind하게 찾았는지 보고하지 않는다.

## 후속 DeFiScope 교차 평가

- `[V]` DeFiScope는 DeFort의 54건을 모두 포함하고 DeFiHackLabs·산업 파트너 사례를 합쳐, 중복 제거 후 90개 앱의 PMA transaction 95건으로 D1을 구성했다. DeFiScope, Section VII, Dataset, Table II.
- `[V]` DeFiScope 저자들은 비공개인 DeFort 코드를 DeFort 저자에게 받아 재실행했다고 명시한다. DeFiScope, Section VII-A.
- `[V]` 확장 D1에서 DeFort는 50/95, 즉 52.6% recall을 보였다. DeFiScope, Abstract, Introduction, Section VII-A, Table IV.
- `[V]` DeFiScope는 95건의 44.2%가 custom DeFi protocol의 non-standard price model을 사용했고, standard exchange-rate 계산에 의존하는 DeFort·DeFiRanger가 이들에 덜 효과적이라고 주장한다. DeFiScope, Abstract, Introduction.
- `[I]` original 52/54와 follow-up 50/95의 차이는 support registry와 original benchmark의 alignment가 일반화를 부풀렸을 가능성을 뒷받침하지만, 사건별 overfitting을 직접 입증하지는 않는다. benchmark 구성, code·configuration version, protocol coverage가 다르기 때문이다.
- `[U]` DeFiScope D1이 DeFort 원 54건을 포함했다고 밝히는데도 DeFort의 전체 성공이 50건으로 원 논문의 52건보다 적다. 어떤 기존 incident가 다르게 판정됐는지와 configuration·version 차이는 양쪽 논문에서 조정되지 않는다.

### 해석 범위

`52/54`는 supported·configured target app의 known-positive incident에서 사건 단위 alert를 확인한 결과로 읽어야 한다. protocol family에 대한 사전 template은 domain knowledge로 허용 가능하지만, 평가 후에 공격별 custom strategy를 추가했다면 configuration leakage가 된다. DeFort는 registry freeze 시점, incident별 strategy 선택, 수동 작업량을 보고하지 않으므로 다음과 같이 판정한다.

- attack-specific overfitting: `[U]` 증거 부족으로 확정 불가
- registry·benchmark coverage alignment: `[I]` 가능성 높음
- unseen·non-standard price model generalization: 후속 50/95에 비추어 original 96.3%보다 크게 낮음
- 보편적 real-world accuracy 96.3% 주장: 평가 범위가 지원하지 않음

### Venue accept와 방법론적 판정의 구분

protocol semantics·price adapter·signature library를 사전 지식으로 사용하는 것은 domain-specific security system에서 본질적으로 부적절하지 않다. DeFort는 behavior automaton, modular price strategy, on-chain detector·analyzer, historical·live evaluation을 통합한 system contribution으로 채택될 수 있다. 그러나 venue accept는 registry freeze, blind generalization, hard-negative precision, causal component accuracy가 검증됐다는 증거가 아니다. 따라서 contribution의 실용성과 evaluation claim의 범위를 분리해 판정한다.

## DQ-08에 주는 증거

DeFort는 protocol-specific knowledge를 완전히 제거하는 설계보다 다음 구조를 지지한다.

1. protocol-independent behavior core와 protocol-specific value adapter를 분리한다.
2. adapter가 제공하는 것은 단순 함수명이 아니라 `어떤 상태에서 어떤 경제값을 계산하는가`여야 한다.
3. adapter가 없는 경우 임의 가격을 만들지 않고 `UNKNOWN_VALUE` 또는 `UNSUPPORTED_VALUE_MODEL`을 출력한다.
4. template·signature·manual custom strategy별 coverage와 작성 비용을 따로 보고한다.
5. adapter 유무에 따른 value recovery, causal-chain completion, final detection 성능을 분리 평가한다.

BeltFinance FN은 복잡한 protocol value model을 trace만으로 자동 복원하기 어렵다는 직접 증거이고, Discover FN은 필요한 return-value 관측이 없을 때 adapter만으로도 해결되지 않을 수 있다는 증거다.

## 가져올 수 있는 것

- attack family별 pattern보다 상위 수준에서 detection stage를 orchestration하는 behavior state model
- current value, historical reference, bound, profit을 서로 다른 계산 모듈로 분리하는 구조
- protocol-independent core와 protocol-specific price adapter의 분리
- `associated function`과 `root cause`를 구분하는 표현
- incident detection, behavior analysis, live monitoring을 서로 다른 RQ로 평가한 구성
- false negative에서 `unsupported value model`과 `missing observation`을 분리한 오류 분석

## 그대로 가져오면 안 되는 것

- own-pool historical anomaly를 곧바로 manipulated value로 확정
- price-related call 존재를 value consumption의 증명으로 간주
- abnormal 이후 양의 profit을 manipulation-attributable gain으로 간주
- 가격 이상을 만든 주소 또는 이익 주소를 곧바로 attacker로 간주
- 손실 token flow가 있는 pool·pair를 최종 victim/loss bearer로 간주
- `∃ profitable address subset`을 동일 공격자 집단의 수익으로 간주
- D2의 공개 사고 부재를 완전한 negative ground truth로 간주

## 한 문장 결론

> DeFort는 protocol별 current price와 weighted historical bound를 이용해 abnormal pool을 찾고 관련 주소의 token profit을 결합하는 실용적 incident detector를 제공하지만, distorted value의 독립 reference, return-value consumption, control-based attribution, canonical P&L과 counterfactual loss를 구성하지 않으므로 우리의 causal-evidence gap을 **지원**한다.
