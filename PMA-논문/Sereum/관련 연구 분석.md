## 관련성 판정

- 분류: `인접 탐지 / instruction-level dataflow / runtime enforcement`
- 상태: **`PROPOSED` — PMA 핵심 비교 대상이 아니라 causal-evidence 구성요소 참고 대상**
- `[V]` Sereum은 PMA가 아니라 재진입 공격을 대상으로 한다. 근거: Sections I, III-IV.
- `[V]` storage read가 실제 연산을 거쳐 조건 분기에 영향을 주었는지를 opcode 수준에서 복원한다. 근거: Sections IV-V-A, Figures 8-9.
- `[I]` PMA 연구에는 “경제값을 조회한 호출이 존재함”보다 강한 “그 반환값이 의사결정·정산에 실제 사용됨”이라는 edge를 설계하는 참고가 된다.
- 직접 비교 대상이 아닌 이유: 가격 개입·왜곡·reference·DeFi semantic action·손익 귀속을 정의하거나 출력하지 않는다.

# 2. 논문이 푸는 문제

## 저자의 문제 정의

- `[V]` 이미 배포된 legacy contract를 코드 수정과 contract semantic knowledge 없이 재진입 악용으로부터 보호할 수 있는지 묻는다. 근거: Section I, Research Question.
- `[V]` 실제 트랜잭션 실행 중 inconsistent state를 이용하는 재진입을 감지하고 차단한다. 근거: Sections IV-V.

| 항목 | 판정 | 근거 |
|---|---|---|
| 분석 단위 | `[V]` 하나의 Ethereum transaction 내부 contract invocation tree | Sections IV-V-B |
| 시간 범위 | `[V]` transaction-local | Sections IV-V |
| 주 실행 시점 | `[V]` 실행 중(runtime/inline) | Abstract, Sections I·IV |
| 평가 시점 | `[V]` 과거 transaction replay | Section VI-A |
| 출력 | `[V]` reentrancy violation 경보와 실행 중단 | Sections IV-V-B |
| 대응 | `[V]` transaction abort와 모든 state change·Ether transfer rollback; passive warning mode도 가능 | Sections I, V-B |
| 포렌식 설명 | `[NR]` attacker cluster, beneficiary, victim, loss, P&L schema 없음 | 전 방법론·평가 |

## 저자의 핵심 주장

| 주장 | 구분 | 근거 위치 | 검증 방식 | 현재 판단 |
|---|---|---|---|---|
| legacy contract를 수정하지 않고 재진입을 막을 수 있다 | 저자 주장 | Abstract, Sections I·IV | 수정 geth에서 transaction replay | `[V]` prototype 수준에서 검증 |
| contract semantics 없이 동작한다 | 저자 주장 | Abstract, Section I | bytecode runtime monitor | `[V]` source/ABI 없이 실행하지만 이 때문에 정상 의미를 구분하지 못하는 오탐 존재 |
| 실제 실행 경로를 추적해 advanced reentrancy를 찾는다 | 저자 주장 | Sections III-V | 세 crafted attack transaction | `[V]` 세 제시 공격에서 성공; 모든 변형에 대한 recall은 미검증 |
| false-positive rate가 약 0.06%다 | 저자 주장 | Abstract, Section VI-A | 77,987,922 transaction replay | `[V]` 전체 transaction 대비 경보율에 가까운 측정; alert precision으로 해석하면 안 됨 |
| runtime overhead가 작다 | 저자 주장 | Section VI-C | 50 blocks × 10,000회 | `[V]` 해당 환경에서 9.6%; 현대 chain에 대한 일반화는 미검증 |

## 우리의 문제와의 관계

- 직접 제공하는 부분:
  - 실제 실행된 call relation
  - storage address에서 조건 분기로 이어지는 data dependency
  - 재진입 호출과 뒤늦은 state write의 순서·관계
- 전제로 주어지는 부분:
  - 재진입 위험은 persistent storage에 의존한 control-flow와 뒤늦은 update로 나타난다는 detection predicate
- 다루지 않는 부분:
  - 가격·평가값의 생성과 정상 reference
  - 왜곡 판정
  - DeFi action semantics
  - 경제적 settlement 및 asset/debt 결과
  - attacker·victim·beneficiary·loss bearer 귀속
  - 실제 P&L과 counterfactual gain/loss
- 이 논문만으로 말할 수 없는 것:
  - 동적 taint가 PMA의 경제적 인과성을 충분히 증명함
  - EVM의 모든 데이터 흐름을 의미 손실 없이 복원함
  - 경보 49,080건의 precision이 높음

## 범위 반례

- `[V]` storage 값이 분기 없이 Ether amount나 call input에 직접 사용되는 공격은 기본 sink 정의에서 빠진다. Section IV.
- `[V]` 실행되지 않은 잠재 취약 경로는 dynamic monitor가 관측하지 않는다. Sections IV, VI.
- `[V]` constructor callback, tightly coupled trusted contracts, manual mutex는 정상인데도 predicate와 일치할 수 있다. Section VI-B.
- `[I]` 여러 transaction이나 block에 걸친 상태 조작은 transaction-local call tree의 범위를 벗어난다.

아래 판정은 PMA의 경제 인과 사슬을 기준으로 하되, Sereum의 재진입 domain에서 제공하는 실행 증거를 별도로 표시한다.

|---|---|---|---|---|---|

| 통제 관계·주소 군집 | 없음 | - | `0` | 중간 contract와 beneficiary를 군집하지 못함 | `[NR]` |
| 개입 | reentrant call | call/return trace | `D` | PMA 가격 개입과 무관 | Sections III-IV |
| 상태 변화 | storage write attempt | `SSTORE`와 storage address | `D` | 고수준 상태 의미 없음 | Section V-B |
| 왜곡된 경제값 | 없음 | - | `0` | 가격·담보가치 등 미지원 | `[NA]` |

표의 `D`는 해당 논문의 재진입 domain에서 원시 실행으로부터 직접 복원한다는 뜻이다. 이것을 PMA의 경제 요소가 직접 복원된 것으로 해석하면 안 된다.

## 인과 연결의 강도

- `[V]` 논문이 직접 연결하는 가장 긴 경로:

  ```text
  external call
    → same-contract re-entry
    → SLOAD(A)
    → arithmetic/logic/comparison dataflow
    → JUMPI condition
    → return to earlier invocation
    → SSTORE(A) attempt
    → abort/rollback
  ```

- `[V]` 이벤트의 인접성을 data dependency로 간주하지 않고 실제 stack/memory taint를 추적한다.
- `[I]` 이 경로는 프로그램 의존성 증거는 강하지만, 왜 해당 값이 경제적으로 왜곡되었는지와 누가 이익을 얻는지는 말하지 않는다.
- 완전한 PMA causal witness가 되지 못하는 이유: distortion/reference, semantic settlement, asset flow, actor attribution, counterfactual calculation이 없다.

# 8. Detection, Discrimination, Hard Negatives

## 판정 규칙

```text
같은 transaction 안에서
  같은 contract가 재진입되고
  재진입 invocation의 JUMPI 조건이 storage address A에 의존하며
  이전 invocation이 외부 호출 뒤 A에 SSTORE를 시도하면
  violation으로 판정하고 abort한다.
```

이는 단순한 `CALL 이후 SSTORE` 규칙보다 구체적이다. 실제 재진입이 있어야 하고, 뒤늦게 쓰는 주소가 재진입 실행의 control-flow에 사용된 주소와 같아야 한다.

## 정상 반례와 오탐

| 유형 | 왜 혼동되는가 | 필요한 추가 정보 | 논문 처리 |
|---|---|---|---|
| Packed struct field | 다른 field가 같은 32-byte slot을 공유 | source/type/field sensitivity | 오탐 원인 분석 |
| Storage deallocation | `delete`와 0 대입이 같은 bytecode 형태 | source 또는 별도 deallocation 의미 | 오탐 원인 분석 |
| Constructor callback | 자식이 정보를 얻으려고 부모를 정상 재호출 | trust·constructor semantics | 피해야 할 개발 패턴으로 제안 |
| Tight contract coupling | 신뢰 contract의 복잡한 상호 호출 | contract trust relation | 신뢰를 모르므로 오탐 가능 |
| Manual mutex | 방어용 lock update가 위험 패턴과 일치 | lock semantics와 전 함수 보호 검증 | bytecode 수준에서 구별 곤란 |

## Hard-negative 관점의 판단

- `[V]` 논문은 오탐 유형을 구체적으로 분석한다. Section VI-B.
- `[I]` 그러나 정상 사례 모집단을 별도 benchmark로 만들고 분류 성능을 평가하지는 않는다.
- `[I]` 논문은 일부 정상 패턴을 “나쁜 개발 관행”으로 보지만, runtime detector의 경보 정확성과 개발 권고는 분리해서 해석해야 한다.
- PMA 연구에 주는 교훈: 명령어 dataflow가 정확해도 source-level 의미와 주체 간 trust가 없으면 공격/정상 판정은 닫히지 않는다.

# 9. Evaluation과 Ground Truth

## 평가 구성

| 평가 항목 | 데이터 | 결과 | 검증 범위 |
|---|---|---|---|
| Historical replay | Ethereum block 4,500,000까지, DoS 대상 block 제외 | 77,987,922 tx 중 49,080 경보 | 실행된 과거 transaction |
| Contract grouping | 93,942 created contracts | 52 관련 contract → 동일·유사 코드 기준 16 그룹 | 경보 집중도 |
| Manual validation | 16 그룹 중 source 확인 가능 6 | DAO와 DSEthToken exploit 확인 | source 없는 사례 의미는 불완전 |
| Known exploit | DAO | 2,294 attack tx | 알려진 단일 사건 family |
| Benign drain | DSEthToken | 43 tx | exploit 동작과 actor intent의 차이 |
| Crafted advanced attacks | cross-function, delegated, create-based 각 1 | 세 공격 모두 탐지 | 제시한 세 test case |
| Performance | 50 blocks × 10,000회 | 9.6% runtime overhead | 특정 geth·hardware·block sample |
| Memory | 동일 benchmark | 9,252 MB → 9,767 MB | client 전체 평균 |

## Ground truth의 강도

- `[V]` DAO는 알려진 실제 공격으로 확인했다.
- `[V]` DSEthToken은 재진입 drain이지만 개발자가 자금 보호를 위해 실행했다. 따라서 실행 패턴만으로 악성 의도를 판정할 수 없음을 보여준다.
- `[V]` source가 없는 contract는 trace와 disassembly로 부분 분석했으며 semantics를 완전히 복원할 수 없다고 논문이 인정한다.
- `[I]` 49,080/77,987,922 = 0.063%는 전체 transaction 대비 경보 비율이다. 모든 비공격 transaction에 대한 확정된 FP 수가 아니므로 이를 alert precision으로 바꿔 말하면 안 된다.
- `[I]` 확인된 두 집단의 2,337건만을 분자로 계산하면 경보 중 약 4.76%지만, 나머지가 모두 오탐으로 확정된 것이 아니므로 이것도 precision이 아니다.
- `[NR]` 전체 실제 재진입 공격 모집단이 없어 recall은 계산되지 않는다.

# 10. Assumptions, Limitations, Reproducibility

## 논문이 드러낸 한계

- `[V]` bytecode storage word 단위라 packed field를 구별하지 못한다.
- `[V]` storage `delete`와 zero assignment의 고수준 의미를 구별하지 못한다.
- `[V]` constructor callback, tightly coupled contract, manual reentrancy lock이 오탐을 만든다.
- `[V]` 기본 sink가 `JUMPI`이므로 분기 없이 외부 호출 인자로 전달된 critical storage value는 직접 다루지 않는다.
- `[V]` source가 없는 경보 contract의 semantics를 완전히 복원하지 못한다.

## 추가 해석상 한계

- `[I]` dynamic-only 분석이라 실행되지 않은 취약 경로는 발견하지 못한다.
- `[I]` transaction-local이라 multi-transaction 경제 조작을 연결하지 않는다.
- `[I]` modified EVM이 필요하므로 보호 범위는 client 배치 방식에 좌우된다.
- `[I]` taint는 data dependence를 보이지만 control dependence 전체나 경제적 인과성을 자동 증명하지 않는다.
- `[I]` 2018년 이전 chain data와 당시 geth에 대한 성능 결과를 현대 EVM chain에 그대로 적용할 수 없다.

## 재현 가능성

| 항목 | 상태 | 비고 |
|---|---|---|
| 논문 원문 | 확인 | 로컬 PDF·추출본 |
| 알고리즘 설명 | 확인 | source/sink, taint propagation, call tree, lock rule 설명 |
| 평가 block 범위 | 부분 확인 | 종료 block과 DoS block 제외는 명시; 제외 목록·완전 실행 설정은 제한적 |
| Sereum 구현 artifact | `[U]` | 현재 공개·빌드 가능 여부를 외부 검증하지 않음 |
| crafted attack code | `[U]` | reference [4] 언급만 확인; 현재 접근·내용 미검증 |
| 전체 alert dataset | `[NR]` | 논문에 공개 위치 보고 없음 |
| end-to-end reproduction | 미수행 | artifact 확인 후 별도 판단 필요 |

# 11. 우리 연구에 대한 판정

## 채택 가능한 사실

- `[V]` 실제 opcode 실행과 shadow state를 추적하면 `SLOAD` 값이 연산을 거쳐 `JUMPI` 조건에 사용된 dataflow를 복원할 수 있다.
- `[V]` 동적 호출 트리는 같은 컨트랙트의 cross-function·중간 contract 경유 재진입을 실제 실행 기준으로 연결할 수 있다.
- `[V]` bytecode-level dataflow만으로는 field semantics와 trusted relationship을 잃어 오탐이 발생한다.
- `[V]` runtime detection과 historical replay evaluation은 구분해야 한다.

## 제안으로만 남길 부분

### `PROPOSED`: PMA consumption evidence로의 확장

```text
source 후보
  SLOAD
  CALL/STATICCALL return data

propagation 후보
  stack / memory / RETURNDATACOPY / arithmetic

sink 후보
  JUMPI condition
  CALL value·calldata
  settlement SSTORE
```

이 확장은 Sereum 논문의 결과가 아니라 우리 연구의 방법론 후보다. 다음이 검증되기 전에는 `ACCEPTED`로 올리지 않는다.

1. 실제 PMA vertical slice에서 왜곡값의 origin부터 정산까지 taint가 보존되는가?
2. direct data dependence와 control dependence를 어떻게 구분·표현하는가?
3. ABI·proxy·library·internal accounting·assembly를 거쳐도 값의 의미를 연결할 수 있는가?
4. 정상 oracle 사용, liquidation, arbitrage 같은 hard negative에서 같은 경로가 생길 때 무엇으로 구별하는가?
5. 값이 소비되었다는 증거와 값이 왜곡되었다는 판정을 어떻게 분리하는가?

### `PROPOSED`: 2단계 분석

- 1단계: call trace·state diff·token flow·semantic action으로 candidate path를 줄인다.
- 2단계: 후보 경로에서만 opcode-level taint/dataflow를 수행해 consumption edge를 검증한다.

이는 비용을 줄일 수 있는 후보 설계지만, 정확도와 누락 위험에 대한 실험 전에는 확정하지 않는다.

## 가져오지 않을 가정

- 모든 중요한 경제값은 `SLOAD`에서 시작한다.
- 모든 소비는 `JUMPI`로 끝난다.
- taint 도달은 곧 가격 왜곡의 인과적 이용이다.
- 재진입된 contract가 언제나 최종 피해자이고 caller가 언제나 최종 공격자다.
- transaction abort detector가 그대로 사후 포렌식 시스템이 된다.

## 최종 관련성 판정

| 질문 | 판정 |
|---|---|
| PMA 핵심 탐지 선행연구인가? | 아니오 |
| 사후 포렌식 연구인가? | 주목적은 아니오 |
| PMA causal graph에 참고 가능한가? | 예, raw data-dependency와 dynamic call relation에 한정 |
| semantic action 설계 근거인가? | 직접 근거 아님 |
| distortion·profit·loss 계산 근거인가? | 아님 |
| 현재 채택 상태 | `PROPOSED` 인접 구성요소 참고 |

# 14. 남은 검증 작업

1. `[UNRESOLVED]` 논문 reference [4]의 공격 예제와 Sereum 구현이 현재 공개·빌드 가능한지 공식 출처에서 확인한다.
2. `[UNRESOLVED]` 구현이 `CALL`, `DELEGATECALL`, `CALLCODE`, `CREATE`의 context와 taint를 정확히 어떻게 넘기는지 코드로 검증한다.
3. `[UNRESOLVED]` PMA 대표 사건 하나에서 external return value가 정산 금액까지 이어지는 instruction-level dataflow를 수동 정답과 대조한다.
4. `[UNRESOLVED]` data dependence만으로 부족한 control dependence 사례를 수집한다.
5. `[UNRESOLVED]` opcode-level 분석 비용을 줄이기 위한 candidate filtering이 실제 소비 경로를 누락하는지 평가한다.

이 검증 전까지 Sereum을 PMA 전체 방법론의 직접 근거로 사용하지 않고, observation/causal-evidence layer의 인접 연구로만 인용한다.
